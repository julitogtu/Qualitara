## VerusLLC conventions

**Layout and naming**
- `VerusLLC.slnx` with `/src` and `/tests` folders, plus a Solution Items folder holding `compose.yaml` and `Directory.Packages.props`.
- Five projects in a Clean Architecture layout: `Api`, `Application`, `Domain`, `Persistence`, and a single test project `Tests` whose folders mirror the layers (`Api/`, `Application/`, `Domain/`, `Persistence/`).
- The Application layer uses CQRS folders, e.g. `Companies/Queries/GetCompanyById/{Query,QueryHandler}.cs`, with `Commands/...` alongside and a `*Validator.cs` per command.
- Records for requests and DTOs; handlers are `internal sealed` with primary constructors; file-scoped namespaces.
- The Api has `Contracts/<Feature>/` for its HTTP request and response types, each with a static `Response.From(dto)` mapper.
- Every project sets `net10.0`, `Nullable` and `ImplicitUsings` itself, because there's no `Directory.Build.props`. The test project pins `LangVersion 12.0`, which is lower than net10's default.

**DI**
- Each layer exposes `AddApplication()` / `AddPersistence()` extension methods, declared in the `Microsoft.Extensions.DependencyInjection` namespace.
- It uses assembly scanning (MediatR and FluentValidation), plus two MediatR pipeline behaviours: unhandled-exception handling and a Polly retry.
- It reads `TimeProvider` from DI and falls back to `TimeProvider.System`.

**Endpoints**
- MVC controllers deriving from an `ApiControllerBase` that carries `[ApiController]`, the `api/[controller]` route and a lazily resolved `ISender`.
- Every action follows the same pattern: `Mediator.Send`, then return `ToProblem(err)` if `IsFailure`, otherwise `Ok(Response.From(...))`.
- Actions declare `[ProducesResponseType<T>]` and take a `CancellationToken`.
- API versioning via the `x-api-version` header; OpenAPI plus the Scalar UI.

**Errors**
- Handlers return `Result<T>` with an `Error(Type, Code, Description)`, and `ToProblem` maps the error type to an HTTP status and ProblemDetails.
- The ProblemDetails title is the machine-readable error code (e.g. `company.not_found`) and it carries a `correlationId` extension.
- As a backstop there's an `ApiExceptionFilterAttribute` (exception type → ProblemDetails) plus a custom `InvalidModelStateResponseFactory`.

**Config**
- Read directly with `Configuration.GetValue("Companies:SeedSampleData", true)`; no `IOptions` classes in the files I read.
- Hosts use `${API_PORT:-5000}`-style environment variables in compose.
- HTTPS redirection only turns on when `ASPNETCORE_URLS` contains an https URL.

**Logging**
- Serilog reads its settings from configuration, enriches from the log context, and sets an `Application` property.
- `UseSerilogRequestLogging` plus a correlation-ID middleware.
- Structured message templates with a fixed prefix, e.g. `"VerusLLC Request: ... {ErrorCode}"`.

**Tests**
- xUnit v3 (`OutputType Exe`); `global using Xunit`; plain `Assert` only. FluentAssertions is pinned centrally but not used here.
- Integration tests go through `WebApplicationFactory` (a `CompaniesApiFactory` with constructor options), and each test creates its own factory and client.
- Assertions read `JsonElement` and check the wire contract, including the exact field set of the response.
- Test names follow `Method_Condition_Outcome`, with `[Theory]` + `[InlineData]` for invalid inputs.

**Compose**
- API and frontend services built from Dockerfiles, with a `/health` healthcheck and `depends_on: service_healthy`. No database, because persistence is in-memory.

**Versions** (central package management)
- EF Core / AspNetCore 10.0.11, xunit.v3 4.0.0, Microsoft.NET.Test.Sdk 18.9.0, MediatR 14.2.0, FluentValidation 12.1.1, Serilog.AspNetCore 10.0.0, Scalar 2.17.3, Polly 8.7.0.
- Testcontainers.PostgreSql 4.15.0. It's Postgres, not SQL Server.

## ADOPT vs DROP for DASH-247

**ADOPT**
| Convention | Reason |
|---|---|
| `.slnx` with `src/` and `tests/` folders | Cheap and consistent with your earlier work. |
| `Directory.Packages.props`, with EF and AspNetCore at 10.0.x | One place for versions; the Testcontainers package becomes `Testcontainers.MsSql`. |
| Add a `Directory.Build.props` (Verus doesn't have one) | Sets `net10.0`, Nullable, ImplicitUsings and TreatWarningsAsErrors once for three projects. |
| An `AddCore()` extension on `IServiceCollection` | Keeps composition in one place and gives the only legitimate spot to register `IClock`. |
| `CancellationToken` on every async path | Costs nothing, and `SqlQueryRaw` accepts it. |
| ProblemDetails for 4xx, with a machine-readable code as the title | A standard shape the Angular client can switch on; only 400 for bad parameters, never 404 for account 20. |
| xUnit v3 with plain `Assert` | FluentAssertions 8 needs a commercial licence and adds nothing to golden-value asserts. |
| `WebApplicationFactory` tests that assert on `JsonElement` | Checks the actual JSON contract, which is what the golden values are about. |
| `Method_Condition_Outcome` test names | Test names then read as specs, e.g. `Pulse_Account20_Returns200InsufficientHistory`. |
| `public partial class Program;` | Required for `WebApplicationFactory`. |
| Structured log templates | Free queryability; use a `Pulse:` prefix instead of `VerusLLC Request:`. |
| Compose with a healthcheck and `depends_on` | SQL Server takes a while to start; the API shouldn't race it. |

**DROP**
| Convention | Reason |
|---|---|
| Separate Domain, Application and Persistence projects | The plan fixes three projects: Api, Core, Tests. Two extra layers for one endpoint cost time and buy nothing. |
| MediatR and pipeline behaviours | A pass-through wrapper around one query; call the service directly. |
| FluentValidation | Three query parameters; a few guard clauses returning ProblemDetails will do. |
| Polly retry behaviour | The aggregation is a single read, and retries hide failures in a 4h demo. |
| API versioning (four packages) | One unversioned endpoint. |
| MVC controllers + `ApiControllerBase` | Minimal APIs mapped with `MapGet` on a route group are less code for one route. |
| `Result<T>`/`Error` framework | One endpoint has about two failure modes (bad parameter, unknown account); handle them inline. |
| `ApiExceptionFilterAttribute` | MVC-only; for minimal APIs use the built-in `AddProblemDetails()` + `UseExceptionHandler()`. |
| Serilog | The built-in console logger covers a demo; one less configuration surface. |
| Correlation-ID middleware | No distributed calls to correlate. |
| Global rate limiter (2 requests/min) | Breaks the dashboard, which calls the API repeatedly. |
| CORS with `AllowAnyOrigin` + `AllowCredentials` | ASP.NET Core rejects that combination; use `WithOrigins(localhost:4200)` or the Angular dev proxy. |
| Scalar UI | Optional; the built-in OpenAPI JSON is enough. Keep Scalar only if it's a one-line add. |
| `TimeProvider.System` fallback | Conflicts with the no-wall-clock rule; use an `IClock` registered only in the composition root. |
| Seeding controlled by a configuration flag at startup | The seed goes in through EF migrations; the plan says never `EnsureCreated`. |
| Test project pinned to `LangVersion 12.0` | No reason to pin below net10's default. |
| `Microsoft.VisualStudio.Azure.Containers.Tools.Targets` | A Visual Studio tooling package with a preview version. |
| A new factory per test | With a SQL Server container per factory that's too slow; share one fixture per collection. |
